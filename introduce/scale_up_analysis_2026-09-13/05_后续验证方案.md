# 把当前局部证据推进为 scale up 结论的最小验证方案

日期：2026-09-13。以下均为**建议实验，未训练、无预测结果**。本次交付只做资料与结果分析，没有提交服务器训练任务。

## 1. 先明确要回答的问题

现有资料最值得验证的假设是：**在本任务、当前输入及训练预算下，增量容量放在交互深度，可能比扩大 Token 宽度更有效。**它与“增加任何参数都有效”不同，也不要求先证明一条幂律。

将问题拆为三种，分别比较：

1. **固定训练数据量**：每个模型看到相同样本、顺序、epoch 和每日测试集，研究同一学习机会下的结构效果；允许计算成本不同。
2. **近似固定 Dense 参数或前向计算量**：比较不同容量分配，研究约 137M 预算下，深度、Token 宽度、FFN 中间宽度分别带来什么。
3. **固定实际训练计算预算**：控制硬件及 worker/PS 规格、有效训练 FLOPs 或设备时间，允许样本暴露量不同，但明确报告；研究实际投入的性价比。

不能用一种设置同时声称“同样本、同计算、同延迟”。目前只具备第一类的历史记录和第二类的静态成本估算，尚无第三类的实测证据。

## 2. 第一阶段：围绕约 137M 的容量分配

沿 Small 的字段分组、双 FFN Block、RMSNorm、PureFlat 和 `[2048,2048,256]` 任务头，固定 T=H=32、Embedding=17，比较下表。M 是单套 SwiGLU 的中间宽度。

| ID | D | L | M | Dense 参数静态预算 | 相对 S3 | 回答的问题 |
|---|---:|---:|---:|---:|---:|---|
| S2_anchor | 256 | 2 | 704 | 102,356,069 | -25.33% | 两层 Small 复现锚点 |
| S3_anchor | 256 | 3 | 704 | 137,081,957 | 0 | 三层 Small-3 复现锚点 |
| W352_L2 | 352 | 2 | 704 | 138,719,813 | +1.19% | 近参数量下，宽度与深度分配 |
| M1056_L2 | 256 | 2 | 1056 | 137,049,189 | -0.024% | 几乎等参数/矩阵主项下，FFN宽度与深度分配 |
| Base_anchor | — | — | — | 90,341,785 | — | 同日业务锚点 |

这些预算来自当前 PureFlat 家族的矩阵形状，保持其他分支不变，**不是已有实跑参数或效果**。来源及推导见[代码容量审计](03_代码容量与计算口径审计.md)。其中：

\[
P(D,L,M)=5,295,973+D^2+107,589D+64L(3DM+2M+2D).
\]

固定 M=704 时，主体成本近似随 LD 而非 LD² 增长；M 随 D 比例增长时，才出现常见的 LD² 主项。因此必须在任何“扩宽”实验名称中注明 M 是否固定。

M1056_L2 与 S3 的差别非常小：参数少 32,768（约 0.024%），两者的 LD M 完全相同。它比“Small-3 vs D512 E2”更接近真正的等预算深度对照。W352_L2 的 D 可被32整除，但其 head 分片宽度变为11，可能具有不同内核效率；参数接近仍需实测。

**执行前需要代码准备**：现存 Small、Small-3、E2 均有固定架构和期望参数量断言，不能只改 args 就运行上述新点。应在单一可配置实现中保留字段覆盖/checksum、形状约束及解析/建图参数一致性校验，允许批准的 D/L/M 网格；先确认原 S2/S3 的前向路径和参数统计一致，再使用这一实现统一重跑。不要把绕过构造器的静态计算当成建图验证。本次不修改训练源码或生成貌似可直接提交的配置。

建议先对上述五个点使用同一新日期链、至少三个 Dense 初始化种子；成本紧张时先用一个共同种子筛查可运行性，正式结论仍保留独立种子复跑。若只有单种子预算，就将结论限定为该训练链的描述性观察。

三个种子是初步波动评估的起点，不保证充分统计功效。追加种子、测试日期或样本的规则应预注册，不以“当前是否达到显著”临时决定停止或继续。

## 3. 第二阶段：确认局部扩容区间和递减收益

第一阶段有可复现收益后，增加 D256/M704/L4（静态 171,807,845 参数），形成 L=2/3/4 三点。固定样本预算下看同日 AUC、BCE、COPC 和实际训练成本；每增加一层计算边际收益：

\[
\Delta_L=\mathrm{AUC}_{L+1}-\mathrm{AUC}_L,
\quad \eta_P=\Delta_L/(P_{L+1}-P_L),
\quad \eta_C=\Delta_L/(C_{L+1}-C_L).
\]

\(\eta_P\) 仅描述当前点之间的局部效率，不是可外推的斜率。若 L4 无收益，说明可能存在局部最优或优化困难；需看训练/验证损失、梯度和计算预算，不能仅凭 AUC 判断为过拟合、饱和或秩坍缩。

若要研究宽度扩展，再增加 D=256/352/512 且 L=2、M=704 的完整序列；另设 M/D 比例固定的序列。不要把这两种宽度实验合在同一拟合中。历史 E2 可作线索，不能代替新日期链下的同步锚点。

## 4. 三个针对性的机制对照

### 4.1 末端与深度：补齐现有 2×2

已有四点是 full-L2（Small）、full-L3（Small-3）、light-L2（Small-1）、light-L3（Small-2）。full/light 同时包含末端 Norm、读出和任务头差异。历史四点只有首日共同记录，不能估计稳定的交互效应。

补齐相同多日窗口与种子后再计算：

\[
I=(A_{full,3}-A_{full,2})-(A_{light,3}-A_{light,2}).
\]

当前首日 I=-0.000127；两种末端下加深都正向，并不支持“只有 full 才能享受 depth scale up”。若要单独归因于 Flatten，需进一步固定输出接口/任务头预算、Norm 仿射粒度、初始化和训练目标。不能把上述整套末端对照改名为 pooling 单算子消融。

### 4.2 输入与主干的预算分配

mature_v1 使用更重的坐标级门控和粗组多 Token 投影，Small-3 使用更重的双阶段主干和大任务头。整套比较提示输入端容量值得研究，但无法证明是哪一个模块负责。

可先做一个桥接点：在固定 Small 主干/末端及近似总参下，仅调整输入门控粒度或粗/细分组投影中的一个；降低其他模块参数用于预算匹配时，必须同时保留未匹配的直接改动对照，避免将补偿减参造成的损失算到输入模块上。记录局部 Token 信息保留、表示谱和梯度，而不是仅看总 P。

### 4.3 早期 v5→v6 的宽度/分组混杂

仓库已有[0814 四点设计](../rankmixer_ablation_20260814_report.md)与对应[结果模板](../rankmixer_ablation_20260814_results.csv)，但模板状态仍为 `not_run`。其 E2 是“v5 哈希分组 D512”，与本报告已有结果中的“v6-E2 PureFlat”不是同一个方案。

若继续追问 v5→v6 的来源，执行哈希 D1024、哈希 D512、语义 D512 三点及同日 Base；必要时补语义 D1024。旧设计中“不再做纯深宽扩展”是当时的排队取舍，不妨碍本次用户明确提出的 scale up 分析与新证据下的实验建议。

## 5. 数据与计算扩展：避免把续训天数当作数据 scaling law

历史协议每训练一天、测试集也移动一天，新增数据、训练步数、稀疏参数状态及测试分布一起改变。对同日 Base 的 gap 可以削弱公共日期波动，却不能完全消除架构与日期的交互。因此现有续训曲线只能称为训练链轨迹。

若验证 data scaling，固定同一训练时间窗及其之后的冻结测试集，以请求/用户稳定抽样构建嵌套 25%/50%/100% 数据子集；同一 embedding 初始 checkpoint，Dense 全部冷启。分别记录 unique examples、实际 exposures、更新步数、epoch 和时间。固定 epoch 与固定更新数是两种不同实验，应分开命名；不要通过未来日期的 sparse checkpoint 泄露测试期信息。

共同Sparse checkpoint应早于抽样训练池；若其中已包含训练池信息，则必须将命题限定为“给定预训练Embedding条件下的增量数据扩张”，并记录其预训练数据范围，不能当作从零开始的总数据需求。

若验证 compute scaling，固定测试集及可用数据池，记录各模型到预先指定 FLOPs/设备小时预算时的验证损失。优化器/学习率可做等量调参，不能只给大模型或小模型更多调参预算。至少多个规模点及多个预算点才能讨论曲线形状；拟合使用固定口径验证 BCE/log loss，并做留出规模点预测，不直接对混合架构 AUC 或 AUC−Base 拟合幂律。

## 6. 实验记录和统计

每个 run 保存：代码 commit 和实际 diff/源码哈希、完整生效配置、任务 ID、Dense 初始化种子、三桶特征与分组 checksum、初始 sparse checkpoint、每日日志及 restore 摘要、样本过滤/顺序、实际样本量、训练步数、硬件/worker/PS、精度、batch、优化器/LR 调度、最终 checkpoint、逐样本预测及 validator 版本。

结果同时报告：

- 同日官方 AUC、配对 ΔAUC、分层排序效果、BCE/log loss；多日等权均值与 pooled AUC 分开。
- COPC 及 `|COPC−1|`；后者的日期均值是描述量，不能代表总体校准误差。
- Dense/sparse/total 参数；静态前向 FLOPs、实际训练时长、step time、设备内存、吞吐和部署时延分别统计。
- 搜索请求内候选相关性，以及同用户跨请求、跨日相关性；依据实际依赖选择 cluster 单位，并给出多 Dense 种子的波动。

现有工具为 [paired_auc_analysis.py](/Users/goku/Documents/Codex/RSA_code_0816/src/models/rankmixer/tools/paired_auc_analysis.py:1)，采用按 `search_id` 哈希分组的 delete-one-group jackknife，读取四列 `search_id / example_id / label / prediction`，通过桶计数及指纹核对样本。AUC 是直方图近似；正式点值仍以生产 validator 为准，应检查 bins 加密后的差值稳定性及残余用户相关性。没有逐样本预测时不生成 CI，不对几日均值做伪独立 t 检验。

可在已有**本地真实预测**后按下式使用（路径是占位符，当前未执行）：

```bash
python3 src/models/rankmixer/tools/paired_auc_analysis.py \

```

以正式晋级前预注册的业务阈值和配对 CI 决策。旧工具的 `+0.0002` 是已有设计门槛，不是本业务普适显著性阈值；“CI 包含0”只表示不能拒绝零差异，**不证明工程等价**。若要判定等价，应使用预注册等价区间，并要求置信区间落在区间内，或采用适当的等价检验。

## 7. 可交付结论的升级条件

| 想使用的表述 | 最少还需要的证据 |
|---|---|
| Small 的局部 depth scale up 可复现 | 新日期链、独立种子、配对统计、配置留痕 |
| 约137M下深度优于宽度分配 | W352_L2/M1056_L2同步同样本对照，以及成本实测 |
| 存在稳定扩容区间或边际递减 | 同族L/D/M多点、稳定测试集、足够训练预算 |
| 是数据不足/过拟合/秩坍缩导致 | 各自对应的训练/验证损失、数据预算干预、表示谱与干预证据 |
| 实际训练或线上更高效 | 同硬件吞吐、设备时间、内存与延迟，不能仅用P或静态FLOPs |
| 可预测的 scaling law | 固定目标/口径的多规模多预算数据、拟合残差和留出点验证 |

在这些条件补齐前，可以明确报告已经观察到的局部规律；没有必要为了使用“scale up”一词而把证据夸大成全局定律。
